# 050 — SV-050 — Basic Constraints

SystemVerilog constraints are used to **control the values generated by randomization**.

Constraints are declared inside a class using a `constraint` block.

### Constraint Syntax

```systemverilog
constraint data_range {
    data >= 10;
    data <= 50;
}
```

When `randomize()` is called, the simulator generates values that satisfy the constraint.

### Relational Constraints

Common relational operators used in constraints include:

| Operator | Meaning |
|---|---|
| `==` | Equal to |
| `!=` | Not equal to |
| `<` | Less than |
| `>` | Greater than |
| `<=` | Less than or equal to |
| `>=` | Greater than or equal to |

For example:

```systemverilog
constraint address_range {
    address >= 100;
    address < 200;
}
```

This restricts `address` to values from `100` through `199`.

### Why it matters in verification

Constraints allow random stimulus to remain **legal and meaningful**. Instead of generating completely unrestricted values, the verification environment can define valid ranges and relationships for transactions.

### Complete Runnable Code

```systemverilog
module sv_050_basic_constraints;

    class transaction;

        rand int data;
        rand int address;

        // Relational constraints
        constraint data_range {
            data >= 10;
            data <= 50;
        }

        constraint address_range {
            address >= 100;
            address < 200;
        }

        function void display(int count);
            $display("Transaction %0d: data = %0d | address = %0d",
                     count, data, address);
        endfunction

    endclass


    transaction trans;
    int count;

    initial begin

        trans = new();

        for (count = 1; count <= 5; count++) begin

            if (trans.randomize())
                trans.display(count);
            else
                $display("Randomization failed");

        end

    end

endmodule
```

### Expected Output

The exact values vary because they are randomly generated.

Example:

```text
Transaction 1: data = 37 | address = 154
Transaction 2: data = 12 | address = 183
Transaction 3: data = 48 | address = 121
Transaction 4: data = 25 | address = 197
Transaction 5: data = 41 | address = 109
```

The generated values always satisfy:

```text
10 <= data <= 50
100 <= address < 200
```

**Key concepts:** `constraint` blocks, relational constraints, legal random values, constraint solver, constrained `randomize()`.
