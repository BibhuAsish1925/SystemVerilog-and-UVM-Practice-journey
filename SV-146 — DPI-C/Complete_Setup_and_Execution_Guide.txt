# SV-146 — DPI-C in Vivado 2025.1 — Complete Setup and Execution Guide

## 1. What We Are Doing

**DPI-C (Direct Programming Interface — C)** allows SystemVerilog code to call functions written in C.

For SV-146, our flow was:

```text
SystemVerilog Testbench
        │
        │ import "DPI-C"
        ▼
     C Function
        │
        │ performs calculation
        ▼
      Result
        │
        ▼
SystemVerilog Testbench
```

Our example used:

```text
a = 25
b = 17
```

The C function calculated:

```text
25 + 17 = 42
```

and SystemVerilog received `42`.

# 3. Important Point — Do Not Add the `.c` File Normally in Vivado

For normal Vivado simulation sources, we usually add:

```text
.v
.sv
.vh
```

etc.

But the DPI-C `.c` file is handled differently.

We **do not add `sv_146_dpi_c.c` through the normal Vivado Add Sources flow**.

Instead, we compile the C file using:

```text
xsc
```

`xsc` is the Vivado/XSim compiler flow used for C/C++ DPI code.

---

# 7. Step 1 — Compile the C DPI Code Using XSC

We ran:

```tcl
exec xsc sv_146_dpi_c.c
```

### What `xsc` does

It compiles the C source code and creates the DPI library used by XSim.

Our output included:

```text
Done compilation
```

and:

```text
Done linking: "xsim.dir/work\xsc\dpi.a"
```

Therefore the C code was successfully compiled.

The important generated library was:

```text
xsim.dir/work\xsc\dpi.a
```

So:

```text
sv_146_dpi_c.c
       ↓
      xsc
       ↓
    dpi.a
```

---

# 8. Step 2 — Compile the SystemVerilog Testbench

Next we compiled the SystemVerilog file:

The output showed:

Therefore:

```text
sv_146_dpi_c_tb.sv
          ↓

   SystemVerilog compiled
```

---

# 9. Step 3 — Elaborate and Link the DPI Library

This is the important connection step.

We ran:

```tcl
exec xelab sv_146_dpi_c_tb -sv_lib dpi
```

### Why `-sv_lib dpi` is important

The SystemVerilog code contains a DPI-C function declaration.

The actual implementation is inside the C file.

Therefore XSim needs to know which DPI library contains the C implementation.

That is what:

```text
-sv_lib dpi
```

does.

The command successfully produced:

```text
Built simulation snapshot work.sv_146_dpi_c_tb
```

There was no:

```text
undefined reference
```

error.

This was particularly important because our earlier attempt had failed with an error like:

```text
undefined reference to `sv146_c_add'
```

The successful `xsc` + `xelab -sv_lib dpi` flow fixed that problem.

---

# 10. Step 4 — Run the Simulation

Finally, we executed:

```tcl
exec xsim sv_146_dpi_c_tb -runall
```

This started XSim and ran the complete testbench.
