SV-149 — Multi-Language EDA Interface
Complete Setup and Execution Guide
============================================================

1. OVERVIEW
============================================================

SV-149 demonstrates how SystemVerilog, C, Python, Perl, and Tcl
can be used together in an EDA-oriented workflow.

The project uses:

    Tcl
     |
     +----> Python
     |
     +----> Perl
     |
     +----> Vivado/XSim
                |
                +----> SystemVerilog
                           |
                           +----> DPI-C
                                     |
                                     +----> C

The same simple calculation is used throughout the demonstration:

    25 + 17 = 42

The purpose of this project is not to create a complex verification
environment, but to understand how different languages can interact
in a practical EDA workflow.

8. SYSTEMVERILOG DPI-C STRUCTURE
============================================================

The SystemVerilog testbench imports the C function using DPI-C.

The important declaration is:

    import "DPI-C" function int sv149_c_add(
        input int a,
        input int b
    );

The SystemVerilog testbench calls:

    c_result = sv149_c_add(a, b);

with:

    a = 25
    b = 17

The expected result is:

    42


9. C DPI-C IMPLEMENTATION
============================================================

The C file contains the implementation:

    #include "svdpi.h"
    #include <stdio.h>

    DPI_DLLESPEC
    int sv149_c_add(int a, int b)
    {
        int result = a + b;

        printf("[C] C function: %d + %d = %d\n", a, b, result);

        return result;
    }

The function name and argument/return types must match the
SystemVerilog DPI-C declaration.


10. IMPORTANT DPI-C VIVADO RULE
============================================================

The C file should NOT be added through the normal Vivado
Add Sources flow as an HDL source.

For this project, the C DPI implementation is compiled using:

    xsc

The generated DPI library is then linked during elaboration using:

    xelab -sv_lib dpi


11. COMPILE THE C DPI CODE
============================================================

Run:

    exec xsc sv_149_multilang.c 2>@1

The:

    2>@1

part redirects stderr to stdout.

This is important because GCC may print warnings while xsc
successfully completes compilation.

The tested compilation produced:

    Done compilation
    Done linking: "xsim.dir/work\xsc\dpi.a"

The generated library is:

    xsim.dir/work\xsc\dpi.a

A warning such as:

    warning: 'dllimport' attribute ignored

does not necessarily mean that compilation failed.

For this project, xsc successfully compiled and linked the DPI
library, and the C function subsequently executed correctly.

18. IMPORTANT TCL SYNTAX NOTE
============================================================

Tcl uses square brackets for command substitution.

For example:

    [exec python sv_149_multilang.py]

means that Tcl should execute the command inside the brackets.

Therefore, literal text such as:

    [TCL]

must not be written directly as:

    puts "\n[TCL] Tcl execution started"

because Tcl interprets:

    [TCL]

as a Tcl command.

The correct form is:

    puts "\n\[TCL\] Tcl execution started"

The backslashes prevent Tcl from interpreting the square brackets
as command substitution.

22. TROUBLESHOOTING
============================================================

Problem 1:
    invalid command name "TCL"

Cause:
    Literal [TCL] was interpreted by Tcl as command substitution.

Incorrect:

    puts "\n[TCL] Tcl execution started"

Correct:

    puts "\n\[TCL\] Tcl execution started"


Problem 2:
    xsc appears to compile but Tcl stops with a warning.

Cause:
    GCC warning output is being returned through stderr.

Recommended command:

    exec xsc sv_149_multilang.c 2>@1

This redirects stderr to stdout so Tcl can continue when xsc
successfully completes.


Problem 3:
    DPI-C undefined reference during elaboration/linking.

Example:

    undefined reference to `sv149_c_add'

Possible cause:
    The C DPI implementation was not compiled or linked.

Run:

    exec xsc sv_149_multilang.c 2>@1

Then:

    exec xelab sv_149_multilang_tb -sv_lib dpi


Problem 4:
    Python command is not recognized.

Check:

    exec python --version

Python must be available from the Vivado Tcl environment.


Problem 5:
    Perl command is not recognized.

Check:

    exec perl -v

Perl must be available from the Vivado Tcl environment.


Problem 6:
    Source file cannot be found.

Check:

    pwd

Then:

    glob sv_149_*

Make sure all five SV-149 project files are in the current
directory.

24. WHAT THIS PROJECT DEMONSTRATES
============================================================

This project demonstrates several useful EDA concepts:

    Tcl
        Used as a master automation/orchestration script.

    Python
        Used as an external scripting language for calculations
        and automation.

    Perl
        Used as another external scripting/automation language.

    C
        Used as a native function called from SystemVerilog
        through DPI-C.

    SystemVerilog
        Acts as the simulation/testbench environment.

    Vivado/XSim
        Compiles, elaborates, links, and runs the simulation.


25. PROJECT LIMITATION
============================================================

The Python and Perl calculations are executed independently by Tcl.

They are not directly communicating with SystemVerilog.

The direct language interface demonstrated in this project is:

    SystemVerilog <--> C

through:

    DPI-C

Tcl acts as the external automation layer that coordinates the
different programs and Vivado/XSim.
